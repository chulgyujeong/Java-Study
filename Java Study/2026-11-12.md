# 1. Collection Framework 개념

## 1-1. Collection이란?

- 데이터를 묶어서 분류하고 쉽게 관리할 수 있도록 만들어진 클래스 및 인터페이스의 집합
- 메모리에서 데이터를 효율적으로 관리하기 위한 자료구조
- CRUD 기능을 활용하여 데이터를 관리
  - Create : 데이터 추가
  - Read : 데이터 조회
  - Update : 데이터 수정
  - Delete : 데이터 삭제

## 1-2. Collection Framework의 특징

- Java에서 제공하는 표준 자료구조 라이브러리
- 개발자들이 동일한 규칙과 구조로 데이터를 관리할 수 있도록 표준화
- 배열의 단점인 고정 크기를 보완하여 가변적으로 데이터 관리 가능
- 데이터의 종류와 사용 목적에 따라 적절한 자료구조 선택 가능

## 1-3. Framework란?

- 일정한 구조와 규칙을 제공하는 개발 환경
- 개발자는 제공된 틀에 맞춰 프로그램을 제작

대표적인 Framework 및 개발 기술

- Spring / Spring Boot
- MyBatis / JPA
- React / Vue
- Docker / Docker Compose
- Jenkins / Kubernetes / GitHub Actions

# 2. Collection의 종류와 구조

Collection Framework의 주요 자료구조

```text
                  Collection
                      |
          ---------------------------
          |                         |
         List                      Set
          |
     ArrayList
     Vector
     LinkedList

                  Map
                   |
          -----------------
          |               |
       HashMap         Hashtable
          |
      Properties
```

※ Map은 Collection 인터페이스를 상속하지 않는 별도의 자료구조이다.

## 2-1. 주요 인터페이스 비교

| 구분 | List | Set | Map |
|---|---|---|---|
| 데이터 구조 | 순차적인 데이터 | 중복 없는 데이터 | 키와 값 |
| 순서 | 유지 | 보장하지 않음 | 구현체에 따라 다름 |
| 중복 | 허용 | 허용하지 않음 | Key 중복 불가 |
| 데이터 조회 | 인덱스 | 반복문 등 | Key |
| 주요 구현체 | ArrayList | HashSet | HashMap |

# 3. List 인터페이스

## 3-1. List의 특징

- 데이터 저장 순서가 유지된다.
- 인덱스(Index)를 사용하여 데이터 관리
- 인덱스는 0부터 시작
- 중복 데이터 허용
- 데이터 추가, 조회, 수정, 삭제가 가능
- 데이터 개수가 증가하거나 감소하는 가변 자료구조

## 3-2. 주요 메소드

| 메소드 | 기능 |
|---|---|
| add(Object) | 데이터 추가 |
| get(int index) | 데이터 조회 |
| set(int index, Object obj) | 데이터 수정 |
| remove(int index) | 인덱스 위치 데이터 삭제 |
| size() | 데이터 개수 확인 |
| clear() | 전체 데이터 삭제 |
| isEmpty() | 데이터 존재 여부 확인 |

## 3-3. List 구현 클래스

### ArrayList

- 배열 기반 자료구조
- 가장 많이 사용하는 List 구현 클래스
- 인덱스를 이용한 조회가 빠름
- 데이터 추가 및 삭제 시 배열 요소 이동이 발생할 수 있음

사용처
- 게시물 목록
- 회원 목록
- 상품 목록
- 검색 결과
- 학생 성적 목록

사용 기준
- 데이터를 자주 조회하는 경우
- 순서를 유지하면서 데이터를 관리하는 경우

### Vector

- ArrayList와 마찬가지로 배열 기반 구조
- 주요 메소드가 동기화(Synchronized)되어 있음
- 멀티스레드 환경에서 개별 메소드의 동시 접근을 제어
- ArrayList보다 동기화에 따른 성능 부담이 발생할 수 있음
- 기존 프로그램 유지보수에서 주로 사용

### LinkedList

- 연결 리스트 기반 자료구조
- 각 데이터가 노드 형태로 연결되는 구조
- 중간 데이터 추가 및 삭제에 유리할 수 있음
- 인덱스를 이용한 조회는 ArrayList보다 느림
- Queue, Deque 등의 자료구조로 활용 가능

# 4. ArrayList 실습

## 4-1. 배열 데이터를 ArrayList로 변환

실습 클래스 : `ArrayList_2`

```java
String[] names = {
    "홍길동", "이순신", "박문수", "심청이", "춘향이"
};

List<String> list = new ArrayList<>();

list = Arrays.asList(names);

for (String s : list) {
    System.out.println(s);
}
```

핵심 개념

- `Arrays.asList()` : 배열을 List 형태로 변환
- 반환된 List는 크기 변경이 불가능
- `add()`, `remove()` 사용이 필요한 경우 새로운 ArrayList로 생성

```java
List<String> list =
    new ArrayList<>(Arrays.asList(names));
```

## 4-2. ArrayList를 활용한 크롤링

실습 클래스 : `ArrayList_3`

목적
- 지니뮤직과 멜론의 음악 차트 데이터 수집
- Jsoup을 활용하여 웹페이지 데이터 크롤링
- 크롤링한 데이터를 ArrayList에 저장
- 두 사이트의 음악 목록 비교

### 지니뮤직 데이터 수집

```java
public ArrayList<String> genieData() {
    ArrayList<String> list = new ArrayList<>();

    try {
        Document doc = Jsoup.connect(
            "https://www.genie.co.kr/chart/top200"
        ).get();

        Elements title =
            doc.select("table.list-wrap a.title");

        for (int i = 0; i < title.size(); i++) {
            list.add(title.get(i).text());
        }

    } catch (Exception ex) {
        ex.printStackTrace();
    }

    return list;
}
```

### 멜론 데이터 수집

```java
public ArrayList<String> melonData() {
    ArrayList<String> list = new ArrayList<>();

    try {
        Document doc = Jsoup.connect(
            "https://www.melon.com/chart/index.htm"
        ).get();

        Elements title =
            doc.select("tr#lst50 div.rank01 a");

        for (int i = 0; i < title.size(); i++) {
            list.add(title.get(i).text());
        }

    } catch (Exception ex) {
        ex.printStackTrace();
    }

    return list;
}
```

핵심 개념

- Jsoup : 웹페이지 데이터 수집
- Document : HTML 문서 객체
- Elements : HTML 요소 집합
- ArrayList : 수집한 데이터를 동적으로 저장

# 5. Collections 주요 메소드와 데이터 집합 연산

ArrayList를 활용하면 여러 데이터 목록을 비교하고 결합할 수 있다.

| 메소드 | 기능 | 집합 연산 |
|---|---|---|
| sort() | 데이터 정렬 | 정렬 |
| removeAll() | 상대 목록에 포함된 데이터 제거 | 차집합 |
| retainAll() | 공통 데이터만 유지 | 교집합 |
| addAll() | 다른 목록의 데이터 전체 추가 | 합집합에 활용 |
| containsAll() | 다른 목록의 모든 데이터 포함 여부 확인 | 부분집합 검사 |

※ List에서 addAll()은 단순히 데이터를 이어 붙이는 것이며 중복도 허용한다. Set에서는 중복을 제거하는 합집합 형태로 활용할 수 있다.

## 5-1. 지니뮤직에만 있는 노래

```java
genie.removeAll(melon);
```

- 지니뮤직 목록에서 멜론 목록에 존재하는 데이터를 제거
- 결과적으로 지니뮤직에만 존재하는 데이터가 남는다.

## 5-2. 멜론에만 있는 노래

```java
melon.removeAll(genie);
```

- 멜론 목록에서 지니뮤직에 존재하는 데이터를 제거
- 결과적으로 멜론에만 존재하는 데이터가 남는다.

## 5-3. 공통으로 가지고 있는 노래

```java
genie.retainAll(melon);
```

- 두 목록에 공통으로 존재하는 데이터만 유지
- 교집합에 해당한다.

## 5-4. 두 목록의 데이터 결합

```java
genie.addAll(melon);
```

- 지니뮤직 목록에 멜론 목록을 추가
- List이므로 중복 데이터가 존재할 수 있다.

## 5-5. 데이터 포함 여부 확인

```java
genie.containsAll(melon);
```

- 멜론의 모든 데이터가 지니뮤직 목록에 존재하는지 확인
- 결과는 boolean형(true / false)

# 6. Generic(제네릭)

## 6-1. 제네릭이란?

- 클래스나 메소드를 정의할 때 데이터형을 미리 지정하지 않고 사용 시점에 결정하는 기능
- 데이터형을 표준화하여 안정적으로 관리
- 클래스의 재사용성을 높이는 기술

## 6-2. 제네릭을 사용하는 이유

1. 데이터형의 안정성 확보
2. 동일한 클래스에서 다양한 데이터형 사용 가능
3. 불필요한 형변환 방지
4. 소스 코드의 간결성 확보
5. 어떤 데이터형을 사용하는지 명확하게 표현

## 6-3. 기본 사용법

```java
ArrayList<String> list =
    new ArrayList<String>();

list.add("홍길동");
list.add("이순신");
```

Java 7 이후에는 다이아몬드 연산자를 사용하여 간결하게 작성 가능

```java
ArrayList<String> list =
    new ArrayList<>();
```

## 6-4. 제네릭 사용 시 주의사항

- 기본형(int, double 등)은 직접 사용할 수 없음
- Wrapper 클래스를 사용

| 기본형 | Wrapper |
|---|---|
| int | Integer |
| double | Double |
| float | Float |
| long | Long |
| char | Character |
| boolean | Boolean |

## 6-5. 와일드카드(Wildcard)

`<?>`

- 어떤 클래스형이 전달될지 명확하지 않은 경우 사용
- 다양한 데이터형을 받아 처리할 수 있음

`<? extends Number>`

- Number와 Number의 자식 클래스만 허용
- Integer, Double, Float, Long 등 사용 가능

```java
public void printList(
    List<? extends Number> list
) {
    for (Number n : list) {
        System.out.println(n);
    }
}
```

# 7. ArrayList를 활용한 데이터 관리 시스템

실습 프로젝트 : BookSystem

목적
- Oracle 데이터베이스에서 도서 정보 조회
- 조회한 데이터를 ArrayList에 저장
- 목록, 상세보기, 검색, 삭제 기능 구현
- 페이지 나누기(Paging) 적용

## 7-1. BookVO

도서 정보를 저장하는 사용자 정의 클래스

```java
@Data
public class BookVO {
    private int no;
    private String title;
    private String poster;
    private String author;
    private Date pubdate;
    private String pages;
    private int price;
}
```

- 하나의 도서 정보를 객체 단위로 관리
- Getter / Setter를 활용하여 데이터 접근
- Lombok의 @Data를 사용하여 관련 메소드 자동 생성

## 7-2. BookSystem

### 데이터 저장 구조

```java
private static ArrayList<BookVO> bList =
    new ArrayList<>();
```

- static 변수이므로 클래스 단위로 공유
- 모든 사용자가 동일한 도서 목록을 참조
- BookVO 객체를 ArrayList에 저장

### Oracle 데이터 조회

```java
static {
    try {
        Class.forName(
            "oracle.jdbc.driver.OracleDriver"
        );

        String url =
            "jdbc:oracle:thin:@xxx.xxx.xxx.xx:xxxx:XE";

        Connection conn =
            DriverManager.getConnection(
                url, "hr", "happy"
            );

        String sql =
            "SELECT no,title,author,poster,pubdate,pages,price "
            + "FROM book ORDER BY no ASC";

        PreparedStatement ps =
            conn.prepareStatement(sql);

        ResultSet rs = ps.executeQuery();

        while (rs.next()) {
            BookVO vo = new BookVO();

            vo.setNo(rs.getInt(1));
            vo.setTitle(rs.getString(2));
            vo.setAuthor(rs.getString(3));
            vo.setPoster(rs.getString(4));
            vo.setPubdate(rs.getDate(5));
            vo.setPages(rs.getString(6));
            vo.setPrice(rs.getInt(7));

            bList.add(vo);
        }

        rs.close();
        ps.close();
        conn.close();

    } catch (Exception ex) {
        ex.printStackTrace();
    }
}
```

핵심 개념

- static 초기화 블록 : 클래스 로딩 시 실행
- JDBC : Java와 Oracle 데이터베이스 연결
- ResultSet : SQL 실행 결과 수신
- ArrayList : 조회한 데이터를 메모리에 저장

## 7-3. 도서 목록 및 페이징

```java
public ArrayList<BookVO> bookListData(int page) {

    final int ROWSIZE = 10;

    int start = (page * ROWSIZE) - ROWSIZE;
    int end = page * ROWSIZE;

    if (end >= bList.size()) {
        end = bList.size();
    }

    ArrayList<BookVO> list =
        new ArrayList<>(bList.subList(start, end));

    return list;
}
```

페이징 계산

| 항목 | 계산 |
|---|---|
| 페이지당 출력 개수 | 10개 |
| 1페이지 시작 인덱스 | 0 |
| 1페이지 종료 인덱스 | 10 |
| 2페이지 시작 인덱스 | 10 |
| 2페이지 종료 인덱스 | 20 |

- subList(start, end) : 지정 범위의 데이터 추출
- end 인덱스는 포함하지 않음
- 페이지별로 필요한 데이터만 반환

※ 실제 서비스에서는 페이지 번호가 1보다 작은 경우, 전체 데이터 개수보다 큰 경우 등의 예외 처리도 필요하다.

## 7-4. 도서 상세보기

```java
public BookVO bookDetailData(int no) {

    BookVO vo = new BookVO();

    for (BookVO bvo : bList) {
        if (no == bvo.getNo()) {
            vo = bvo;
            break;
        }
    }

    return vo;
}
```

- 향상된 for문을 사용하여 전체 데이터 검색
- 도서 번호가 일치하면 해당 객체 반환
- break를 사용하여 불필요한 반복 방지

## 7-5. 도서 검색

```java
public ArrayList<BookVO> bookFindData(
    String title
) {

    ArrayList<BookVO> list =
        new ArrayList<>();

    for (BookVO vo : bList) {
        if (vo.getTitle().contains(title)) {
            list.add(vo);
        }
    }

    return list;
}
```

- contains() : 문자열 포함 여부 확인
- 검색 결과를 별도의 ArrayList에 저장
- 검색 결과가 없더라도 빈 ArrayList 반환

## 7-6. 도서 삭제

```java
public void bookDelete(int no) {

    for (int i = 0; i < bList.size(); i++) {

        BookVO vo = bList.get(i);

        if (no == vo.getNo()) {
            bList.remove(i);
            break;
        }
    }
}
```

- get()으로 객체 조회
- 도서 번호가 일치하면 remove()로 삭제
- 삭제 후 break로 반복문 종료

## 7-7. CRUD와 Collection 연결

| 기능 | Collection 메소드 | BookSystem |
|---|---|---|
| Create | add() | 도서 데이터 저장 |
| Read | get(), for-each | 목록 / 상세보기 |
| Update | set() | 도서 정보 수정 |
| Delete | remove() | 도서 삭제 |
| Search | for-each, contains() | 도서 검색 |

※ 현재 실습에서는 목록, 상세보기, 검색, 삭제를 구현했으며 수정 기능은 확장할 수 있다.

# 8. LinkedList

## 8-1. LinkedList 개념

- 데이터가 노드(Node) 형태로 연결되는 자료구조
- 각 노드는 데이터와 연결 정보를 가지고 있음
- 배열처럼 연속된 메모리 공간을 사용하지 않음

구조

```text
ArrayList

[1] [2] [3] [4]


LinkedList

[1] <-> [2] <-> [3] <-> [4]
```

## 8-2. 특징

- 데이터 순서 유지
- 중복 데이터 허용
- 인덱스 기반 조회는 상대적으로 느림
- 중간 데이터 추가 및 삭제 시 배열 요소 이동이 필요하지 않음
- Queue / Deque 자료구조로 활용 가능

## 8-3. 실습 : LinkedList_1

```java
LinkedList<Integer> list =
    new LinkedList<>();

list.add(1);
list.add(2);
list.add(3);

// 데이터 추가
list.add(4);
list.add(2, 5);

// 데이터 삭제
list.remove(0);

// 데이터 수정
list.set(0, 100);

// 전체 삭제
list.clear();

// 데이터 존재 여부
if (list.isEmpty()) {
    System.out.println("데이터가 없습니다");
}
```

## 8-4. 주요 메소드

| 메소드 | 기능 |
|---|---|
| add() | 데이터 추가 |
| get() | 데이터 조회 |
| set() | 데이터 수정 |
| remove() | 데이터 삭제 |
| size() | 데이터 개수 |
| clear() | 전체 삭제 |
| isEmpty() | 데이터 존재 여부 |

※ LinkedList도 인덱스를 이용한 조회는 가능하지만, 해당 위치까지 이동해야 하므로 ArrayList보다 불리할 수 있다.

# 9. Vector

## 9-1. Vector 개념

- ArrayList와 동일하게 배열 기반 자료구조
- 주요 메소드가 동기화되어 있음
- 멀티스레드 환경에서 개별 메소드의 동시 접근을 제어
- 기존 프로그램 유지보수에서 주로 사용

## 9-2. 특징

- 순서 유지
- 중복 허용
- 인덱스를 이용한 데이터 관리
- 동기화에 따른 성능 부담 발생 가능
- 최근 개발에서는 ArrayList를 더 많이 사용

## 9-3. 실습 : Vector_1

```java
Vector<String> names =
    new Vector<>();

// 추가
names.addElement("홍길동");
names.addElement("심청이");
names.addElement("박문수");

// 삭제
names.removeElementAt(0);

// 수정
names.setElementAt("춘향이", 0);

// 전체 삭제
names.removeAllElements();

// 데이터 개수
System.out.println(names.size());

// 데이터 존재 여부
System.out.println(names.isEmpty());
```

## 9-4. 주요 메소드 비교

| ArrayList | Vector | 기능 |
|---|---|---|
| add() | addElement() | 추가 |
| get() | elementAt() | 조회 |
| set() | setElementAt() | 수정 |
| remove() | removeElement() | 삭제 |
| size() | size() | 개수 |
| clear() | removeAllElements() | 전체 삭제 |

※ Vector에는 기존 List 인터페이스의 메소드도 존재한다.

# 10. Set 인터페이스

## 10-1. Set의 특징

- 중복 데이터를 허용하지 않음
- 인덱스가 없음
- 일반적으로 저장 순서를 보장하지 않음
- 중복 제거가 필요한 데이터 관리에 활용

## 10-2. 구현 클래스

### HashSet

- 해시 알고리즘 기반
- 데이터 저장 순서를 보장하지 않음
- 중복 데이터 자동 제거
- 일반적인 중복 제거 작업에 활용

### TreeSet

- 데이터가 정렬된 상태로 관리
- 기본적으로 오름차순 정렬
- 정렬 및 범위 검색에 활용

## 10-3. 주요 메소드

| 메소드 | 기능 |
|---|---|
| add() | 데이터 추가 |
| remove() | 데이터 삭제 |
| contains() | 데이터 존재 여부 |
| size() | 데이터 개수 |
| clear() | 전체 삭제 |
| isEmpty() | 데이터 존재 여부 |

※ Set에는 List와 같은 get(index), set(index, value) 메소드가 없다.

# 11. Map 인터페이스

## 11-1. Map의 특징

- Key와 Value를 한 쌍으로 저장
- Key는 중복 허용하지 않음
- Value는 중복 허용
- Key를 이용하여 Value 조회
- 순서는 구현 클래스에 따라 달라짐

구조

```text
Key       Value

id   --->  hong
name --->  홍길동
age  --->  30
```

## 11-2. 구현 클래스

### HashMap

- 가장 많이 사용하는 Map 구현 클래스
- Key와 Value를 한 쌍으로 저장
- Key 중복 불가
- 순서를 보장하지 않음

### Hashtable

- 주요 메소드가 동기화되어 있음
- 멀티스레드 환경에서 사용 가능
- 기존 프로그램 유지보수에서 주로 사용

### Properties

- 문자열 Key와 Value를 저장
- 환경 설정 정보를 관리
- 설정 파일을 읽고 저장할 때 활용

## 11-3. 주요 메소드

| 메소드 | 기능 |
|---|---|
| put(key, value) | 데이터 추가 및 수정 |
| get(key) | Key를 이용한 조회 |
| remove(key) | 데이터 삭제 |
| containsKey(key) | Key 존재 여부 |
| containsValue(value) | Value 존재 여부 |
| size() | 데이터 개수 |
| clear() | 전체 삭제 |
| isEmpty() | 데이터 존재 여부 |

## 11-4. 주요 사용처

- Spring에서 데이터 전달
- JSP에서 화면 이동 및 데이터 전달
- 사용자 요청값과 결과값 관리
- MyBatis에서 SQL문장 및 파라미터 관리
- 환경 설정 정보 관리

# 12. Queue와 Stack

## 12-1. Queue

- FIFO (First In First Out)
- 먼저 들어온 데이터가 먼저 나가는 구조
- 네트워크 데이터 처리, 작업 대기열 등에 활용

```text
입력 → [1] [2] [3] → 출력
         먼저 들어온 1부터 출력
```

주요 메소드

| 메소드 | 기능 |
|---|---|
| offer() | 데이터 추가 |
| poll() | 데이터 조회 및 제거 |
| peek() | 데이터 조회 |

## 12-2. Stack

- LIFO (Last In First Out)
- 마지막에 들어온 데이터가 먼저 나가는 구조
- 메소드 호출, 실행 취소, 데이터 처리 등에 활용

```text
       [3] ← 마지막 입력
       [2]
       [1]

       3부터 출력
```

주요 메소드

| 메소드 | 기능 |
|---|---|
| push() | 데이터 추가 |
| pop() | 데이터 조회 및 제거 |
| peek() | 최상단 데이터 조회 |

# 14. Collection 선택 기준 및 핵심 정리

## 14-1. List 구현 클래스 비교

| 구분 | ArrayList | Vector | LinkedList |
|---|---|---|---|
| 자료구조 | 배열 | 배열 | 연결 리스트 |
| 순서 | 유지 | 유지 | 유지 |
| 중복 | 허용 | 허용 | 허용 |
| 인덱스 조회 | 빠름 | 빠름 | 상대적으로 느림 |
| 동기화 | X | O | X |
| 중간 삽입/삭제 | 상대적으로 불리 | 상대적으로 불리 | 조건에 따라 유리 |
| 일반적인 사용 | 매우 높음 | 레거시 | 용도에 따라 |

※ 실제 성능은 데이터 크기, 접근 위치, 반복 작업 등에 따라 달라진다. LinkedList의 중간 삽입·삭제도 해당 위치를 찾는 과정이 필요하다는 점에 주의한다.

## 14-2. 자료구조 선택 기준

| 사용 목적 | 선택 자료구조 |
|---|---|
| 데이터 목록 관리 | ArrayList |
| 빠른 인덱스 조회 | ArrayList |
| 중복 데이터 제거 | HashSet |
| 데이터 자동 정렬 | TreeSet |
| Key와 Value 관리 | HashMap |
| 문자열 환경 설정 관리 | Properties |
| FIFO 데이터 처리 | Queue |
| LIFO 데이터 처리 | Stack / Deque |
| 기존 동기화 기반 코드 유지보수 | Vector |

## 14-3. 실무 활용 연결

| 기술 | Collection 활용 |
|---|---|
| JDBC | Oracle 조회 결과를 List로 저장 |
| Jsoup | 크롤링 데이터 저장 |
| Spring | 요청 및 응답 데이터 관리 |
| MyBatis | 조회 결과를 List로 반환 |
| JSP | 화면 출력 데이터 전달 |
| Swing | JTable 데이터 관리 |
| 웹 프로젝트 | 회원, 게시물, 상품 목록 관리 |

## 14-4. 최종 핵심 정리

1. Collection은 데이터를 효율적으로 관리하기 위한 자료구조 라이브러리이다.
2. List는 순서와 중복을 허용한다.
3. ArrayList는 조회가 많은 일반적인 데이터 관리에 적합하다.
4. LinkedList는 연결 구조를 활용한 데이터 추가 및 삭제에 활용한다.
5. Vector는 주요 메소드가 동기화된 기존 자료구조이다.
6. Set은 중복 데이터를 허용하지 않는다.
7. Map은 Key와 Value를 한 쌍으로 관리한다.
8. Generic은 데이터형을 표준화하여 안정성을 높인다.
9. Collection은 JDBC, 크롤링, Spring, MyBatis 등 다양한 기술에서 활용된다.
10. 실제 개발에서는 데이터의 특징과 사용 목적에 맞는 자료구조를 선택해야 한다.
