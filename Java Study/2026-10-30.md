## 1. 객체지향 프로그래밍의 4대 특성

객체지향 프로그래밍(Object-Oriented Programming)은 데이터와 기능을 하나의 객체로 묶어 프로그램을 설계하는 방식이다.

### 1-1. 캡슐화 (Encapsulation)

- 데이터와 메소드를 하나의 클래스로 묶는다.
- 외부에서 데이터에 직접 접근하는 것을 제한한다.
- `private` 접근지정자와 Getter / Setter를 활용한다.
- 데이터 보호 및 유지보수에 유리하다.

### 1-2. 상속 (Inheritance)

- 기존 클래스의 변수와 메소드를 물려받아 새로운 클래스를 생성한다.
- `extends` 키워드를 사용한다.
- 코드 재사용 및 기능 확장이 가능하다.

### 1-3. 다형성 (Polymorphism)

- 하나의 부모 클래스 타입으로 여러 자식 클래스 객체를 관리할 수 있다.
- 오버로딩과 오버라이딩을 통해 다양한 기능을 구현한다.

### 1-4. 추상화 (Abstraction)

- 여러 클래스의 공통적인 특징을 추출하여 하나의 상위 개념으로 정의한다.
- 추상 클래스와 인터페이스를 활용한다.
- 공통 기능과 개별 기능을 분리하여 설계할 수 있다.

## 2. 상속 (Inheritance)

### 2-1. 상속이란?

기존 클래스의 변수와 메소드를 새로운 클래스에서 사용할 수 있도록 하는 기능이다.

```java
class AA {
    int a, b;

    public void aaa() {
        System.out.println("A:aaa() Call...");
    }
}

class BB extends AA {
    int c;

    public void bbb() {
        System.out.println("B:bbb() Call...");
    }
}
```

```java
public class Main {
    public static void main(String[] args) {
        BB bb = new BB();

        bb.aaa(); // 부모 클래스의 메소드
        bb.bbb(); // 자식 클래스의 메소드
    }
}
```

### 2-2. 상속의 목적

- 코드 재사용
- 프로그램의 간결성
- 유지보수 편의성
- 기존 클래스의 기능 확장

### 2-3. 상속의 형식

```java
class 부모클래스 {
    // 공통 변수와 메소드
}

class 자식클래스 extends 부모클래스 {
    // 추가 변수와 메소드
}
```

### 2-4. 상속 관계

예를 들어 동물이라는 공통 클래스를 만들고 개, 소, 말 클래스를 상속받도록 설계할 수 있다.

```text
          동물
           |
     -------------
     |     |     |
     개     소     말
```

### 2-5. 상속의 특징

- Java 클래스는 단일 상속만 가능하다.
- 모든 클래스는 기본적으로 Object 클래스를 상속한다.
- 생성자는 상속되지 않는다.
- `private` 멤버는 상속 관계에서도 자식 클래스에서 직접 접근할 수 없다.
- `static` 멤버는 상속 관계에서 사용할 수 있지만 객체별로 복제되는 것은 아니다.
- 부모 클래스의 생성자는 자식 객체 생성 과정에서 실행된다.

### 2-6. 상속의 단점

- 부모 클래스와 자식 클래스 사이의 결합도가 높아질 수 있다.
- 부모 클래스 변경이 자식 클래스에 영향을 줄 수 있다.
- 상속 구조가 복잡해지면 가독성이 떨어질 수 있다.

## 3. 다형성 (Polymorphism)

### 3-1. 다형성이란?

하나의 부모 클래스 타입으로 여러 자식 클래스 객체를 참조하여 사용하는 것이다.

```java
class 동물 {
    int a = 100;

    public void run() {
        System.out.println("달린다");
    }
}

class 개 extends 동물 {
    int a = 200;

    @Override
    public void run() {
        System.out.println("개가 달린다");
    }
}

class 소 extends 동물 {
    int a = 300;

    @Override
    public void run() {
        System.out.println("소가 달린다");
    }
}

class 말 extends 동물 {
    int a = 400;

    @Override
    public void run() {
        System.out.println("말이 달린다");
    }
}
```

### 3-2. 다형성 활용

```java
public class Main {
    public static void main(String[] args) {

        동물 animal = new 개();
        animal.run();

        animal = new 소();
        animal.run();

        animal = new 말();
        animal.run();
    }
}
```

실행 결과:

```text
개가 달린다
소가 달린다
말이 달린다
```

### 3-3. 다형성의 핵심

```java
동물 animal = new 개();
```

- `동물` : 참조변수의 타입
- `animal` : 참조변수
- `new 개()` : 실제 생성된 객체

부모 클래스 타입으로 자식 클래스 객체를 참조할 수 있다.

단, 부모 클래스 타입의 참조변수는 컴파일 시점에 부모 클래스에 선언된 멤버를 기준으로 접근할 수 있다.

**중요한 특징**

- 변수 : 참조변수의 타입을 기준으로 접근
- 일반 인스턴스 메소드 : 실제 객체의 오버라이딩된 메소드가 실행

## 4. 오버로딩과 오버라이딩

### 4-1. 오버로딩 (Overloading)

같은 클래스 안에서 동일한 메소드명을 사용하되 매개변수의 개수 또는 데이터형을 다르게 정의하는 것이다.

```java
class Calculator {

    public int add(int a, int b) {
        return a + b;
    }

    public int add(int a, int b, int c) {
        return a + b + c;
    }

    public double add(double a, double b) {
        return a + b;
    }
}
```

특징:

- 메소드명이 동일하다.
- 매개변수의 개수 또는 타입이 달라야 한다.
- 반환형만 다른 것은 오버로딩이 아니다.
- 매개변수 이름만 다른 것도 오버로딩이 아니다.

### 4-2. 오버라이딩 (Overriding)

부모 클래스에서 상속받은 메소드를 자식 클래스에서 재정의하는 것이다.

```java
class Animal {

    public void run() {
        System.out.println("동물이 달린다");
    }
}

class Dog extends Animal {

    @Override
    public void run() {
        System.out.println("개가 달린다");
    }
}
```

특징:

- 상속 관계에서 사용한다.
- 메소드명이 동일해야 한다.
- 매개변수가 동일해야 한다.
- 반환형은 동일하거나 허용되는 공변 반환형이어야 한다.
- 접근지정자의 범위를 축소할 수 없다.
- `@Override`를 사용하면 재정의 여부를 컴파일러가 확인한다.

### 4-3. 접근지정자의 범위

```text
private < default < protected < public
```

오버라이딩 시 접근 범위를 확대할 수 있지만 축소할 수 없다.

| 부모 메소드 | 자식 메소드 |
|---|---|
| protected | protected |
| protected | public |
| public | public |
| public | protected (불가능) |

## 5. 객체 생성과 메모리 구조

### 5-1. 객체 생성

```java
class A {
    int a, b;

    public void aaa() {
        System.out.println("A:aaa()");
    }
}

class B extends A {
    int c;

    public void bbb() {
        System.out.println("B:bbb()");
    }
}
```

```java
B b = new B();
```

자식 클래스 객체를 생성하면 부모 클래스에서 상속받은 멤버와 자식 클래스 고유 멤버를 함께 사용할 수 있다.

### 5-2. 메모리 구조의 이해

```java
B b = new B();
```

개념적으로 다음과 같이 이해할 수 있다.

```text
Stack                    Heap

b --------------------> B 객체
                         |
                         | 부모로부터 상속된 멤버
                         | a, b
                         | aaa()
                         |
                         | 자식 클래스 멤버
                         | c
                         | bbb()
```

실제 JVM 메모리 구조는 이보다 복잡하며, 메소드 코드는 객체마다 복제되는 것이 아니다.

### 5-3. 부모 타입 참조

```java
B b = new B();
A a = b;
```

자식 객체를 부모 타입으로 참조할 수 있다.

```java
A a = new B(); // 가능
B b = new A(); // 불가능
```

이를 업캐스팅(Upcasting)이라고 한다.

## 6. this와 super

### 6-1. this

현재 객체 자신을 가리키는 참조변수이다.

```java
class Student {

    String name;

    public Student(String name) {
        this.name = name;
    }
}
```

- 현재 객체의 멤버변수 접근
- 지역변수와 멤버변수 구분
- `this()`를 이용한 같은 클래스의 다른 생성자 호출

### 6-2. super

부모 클래스의 멤버를 참조하거나 부모 생성자를 호출할 때 사용한다.

```java
class Parent {

    int a = 100;
}

class Child extends Parent {

    int a = 200;

    public void print() {
        System.out.println(this.a);
        System.out.println(super.a);
    }
}
```

실행 결과:

```text
200
100
```

### 6-3. this()와 super()

| 구분 | 의미 |
|---|---|
| this | 현재 객체 |
| super | 부모 클래스 부분 |
| this() | 같은 클래스의 다른 생성자 호출 |
| super() | 부모 클래스 생성자 호출 |

주의사항:

- `this()`와 `super()`는 생성자 내부에서만 사용할 수 있다.
- 반드시 생성자의 첫 번째 문장에 작성해야 한다.
- 하나의 생성자에서 `this()`와 `super()`를 동시에 직접 호출할 수 없다.
- 생성자에서 부모 생성자를 명시하지 않으면 컴파일러가 가능한 경우 `super()`를 삽입한다.

## 7. 생성자 (Constructor)

### 7-1. 생성자란?

객체를 생성할 때 자동으로 호출되는 특별한 메소드이다.

```java
class Human {

    String name;
    String sex;
    String address;
    String phone;

    public Human(String name, String sex,
                 String address, String phone) {

        this.name = name;
        this.sex = sex;
        this.address = address;
        this.phone = phone;
    }
}
```

### 7-2. 생성자의 특징

- 클래스명과 동일하다.
- 반환형이 없다. (void도 작성하지 않는다.)
- 객체 생성 시 호출된다.
- 멤버변수 초기화에 사용한다.
- 오버로딩이 가능하다.
- 생성자를 하나도 작성하지 않으면 기본 생성자가 자동으로 제공된다.

### 7-3. 생성자 오버로딩

```java
class Student {

    String name;
    int age;

    public Student() {
        name = "홍길동";
        age = 20;
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

```java
Student s1 = new Student();
Student s2 = new Student("이순신", 25);
```

### 7-4. 상속과 생성자

```java
class Human {

    String name;

    public Human(String name) {
        this.name = name;
    }
}

class Student extends Human {

    int hakbun;
    String subject;

    public Student(String name) {
        super(name);
    }
}
```

`Student` 객체를 생성하면 부모 클래스인 `Human`의 생성자도 실행되어야 한다.

부모 클래스에 기본 생성자가 없다면 자식 생성자에서 적절한 `super(매개변수)` 호출을 작성해야 한다.

## 8. 클래스의 종류

Java에서 사용하는 주요 클래스 구조는 다음과 같다.

| 종류 | 특징 | 객체 생성 |
|---|---|---|
| 일반 클래스 | 모든 메소드 구현 가능 | 가능 |
| 추상 클래스 | 추상 메소드를 포함할 수 있음 | 직접 생성 불가능 |
| 인터페이스 | 구현 규약을 정의 | 직접 생성 불가능 |
| 내부 클래스 | 클래스 내부에 선언된 클래스 | 형태에 따라 다름 |
| 익명 클래스 | 이름 없이 일회성으로 구현 | 구현 객체 생성 가능 |

## 9. 추상 클래스 (Abstract Class)

### 9-1. 추상 클래스란?

공통적인 기능을 정의하면서 자식 클래스마다 구현 내용이 달라지는 메소드는 선언만 해두는 클래스이다.

```java
abstract class 도형 {

    String color = "검정색";

    abstract void setColor(String color);

    void thick() {
        System.out.println("두께: 10mm");
    }

    abstract void draw();
}
```

특징:

- `abstract` 키워드를 사용한다.
- 추상 메소드와 일반 메소드를 함께 가질 수 있다.
- 변수와 생성자를 가질 수 있다.
- 직접 객체를 생성할 수 없다.
- 상속받은 자식 클래스가 추상 메소드를 구현해야 한다.
- 추상 메소드를 구현하지 않으면 자식 클래스도 추상 클래스로 선언해야 한다.

### 9-2. 추상 클래스 구현

```java
class 선 extends 도형 {

    @Override
    void setColor(String color) {
        this.color = color;
    }

    @Override
    void draw() {
        System.out.println("선을 그린다: 색상은 " + color);
    }
}

class 네모 extends 도형 {

    @Override
    void setColor(String color) {
        this.color = color;
    }

    @Override
    void draw() {
        System.out.println("사각형을 그린다: 색상은 " + color);
    }
}

class 원 extends 도형 {

    @Override
    void setColor(String color) {
        this.color = color;
    }

    @Override
    void draw() {
        System.out.println("원을 그린다: 색상은 " + color);
    }

    @Override
    void thick() {
        System.out.println("두께: 5mm");
    }
}
```

### 9-3. 추상 클래스와 다형성

```java
public class Main {

    public static void main(String[] args) {

        도형 a = new 선();
        a.draw();
        a.thick();

        a = new 네모();
        a.draw();
        a.thick();

        a = new 원();
        a.draw();
        a.thick();
    }
}
```

실행 결과:

```text
선을 그린다: 색상은 검정색
두께: 10mm
사각형을 그린다: 색상은 검정색
두께: 10mm
원을 그린다: 색상은 검정색
두께: 5mm
```

핵심:

- 공통 기능은 부모 클래스에서 구현한다.
- 개별 기능은 자식 클래스에서 구현한다.
- 하나의 부모 타입으로 다양한 객체를 관리한다.

## 10. 인터페이스 (Interface)

### 10-1. 인터페이스란?

클래스가 구현해야 하는 기능의 규칙을 정의하는 설계도이다.

```java
interface A {

    void aaa();

    void bbb();

    void ccc();
}
```

### 10-2. 인터페이스 구현

```java
class B implements A {

    @Override
    public void aaa() {
        System.out.println("aaa 실행");
    }

    @Override
    public void bbb() {
        System.out.println("bbb 실행");
    }

    @Override
    public void ccc() {
        System.out.println("ccc 실행");
    }
}
```

### 10-3. 인터페이스 특징

- `implements` 키워드로 구현한다.
- 여러 인터페이스를 동시에 구현할 수 있다.
- 인터페이스의 일반적인 추상 메소드는 기본적으로 `public abstract`이다.
- 인터페이스의 필드는 기본적으로 `public static final`이다.
- Java 8부터 `default`, `static` 메소드를 구현할 수 있다.
- Java 9부터 `private` 메소드도 사용할 수 있다.

### 10-4. 추상 클래스와 인터페이스 비교

| 구분 | 추상 클래스 | 인터페이스 |
|---|---|---|
| 선언 | abstract class | interface |
| 사용 | extends | implements |
| 상속/구현 | 클래스 단일 상속 | 다중 구현 |
| 변수 | 일반 변수 가능 | 상수만 가능 |
| 생성자 | 가능 | 불가능 |
| 일반 메소드 | 가능 | default, static 등 가능 |
| 목적 | 공통 상태와 기능 공유 | 구현 규칙 정의 |

## 11. 익명의 클래스와 람다식

### 11-1. 익명의 클래스

클래스 이름을 별도로 선언하지 않고 인터페이스를 구현하는 방법이다.

```java
Runnable r = new Runnable() {

    @Override
    public void run() {
        System.out.println("쓰레드 실행");
    }
};

new Thread(r).start();
```

### 11-2. 람다식

함수형 인터페이스를 간결하게 구현하는 표현식이다.

```java
Runnable rr = () -> {
    System.out.println("쓰레드 실행");
};

new Thread(rr).start();
```

### 11-3. 비교

```java
// 익명의 클래스
Runnable r = new Runnable() {
    @Override
    public void run() {
        System.out.println("실행");
    }
};

// 람다식
Runnable rr = () -> System.out.println("실행");
```

`Runnable`은 추상 메소드가 하나인 함수형 인터페이스이므로 람다식으로 구현할 수 있다.

## 12. 객체 재사용 기법

객체지향 프로그래밍의 주요 목적 중 하나는 이미 만들어진 코드를 재사용하는 것이다.

### 12-1. 포함 관계 (Has-A)

기존 클래스를 변경하지 않고 객체를 멤버변수로 포함하여 사용하는 방법이다.

```java
import javax.swing.*;

public class 재사용기법 {

    JFrame f = new JFrame();

    public 재사용기법() {

        f.setSize(640, 400);
        f.setVisible(true);
    }

    public static void main(String[] args) {
        new 재사용기법();
    }
}
```

### 12-2. 상속 관계 (Is-A)

기존 클래스를 상속받아 기능을 확장하거나 재정의하는 방법이다.

```java
class Animal {
    public void run() {
        System.out.println("달린다");
    }
}

class Dog extends Animal {

    @Override
    public void run() {
        System.out.println("개가 달린다");
    }
}
```

### 12-3. 비교

| 구분 | Has-A | Is-A |
|---|---|---|
| 관계 | 포함 관계 | 상속 관계 |
| 방식 | 객체를 멤버변수로 사용 | extends |
| 목적 | 기존 기능을 그대로 활용 | 기능 확장 및 재정의 |
| 예시 | 자동차가 엔진을 포함 | 개는 동물이다 |

## 13. final과 static

### 13-1. final

변경이나 확장을 제한하는 키워드이다.

| 사용 위치 | 의미 |
|---|---|
| 변수 | 값 변경 불가능 |
| 메소드 | 오버라이딩 불가능 |
| 클래스 | 상속 불가능 |

예시:

```java
final int MAX = 100;

final class A {
    // 상속 불가능
}
```

### 13-2. static

클래스에 소속되는 멤버를 선언하는 키워드이다.

```java
class Counter {

    static int count = 0;

    public Counter() {
        count++;
    }
}
```

```java
Counter c1 = new Counter();
Counter c2 = new Counter();

System.out.println(Counter.count);
```

실행 결과:

```text
2
```

특징:

- 객체마다 별도로 생성되는 것이 아니라 클래스 단위로 공유한다.
- 클래스명으로 접근할 수 있다.
- static 메소드에서는 인스턴스 멤버를 직접 사용할 수 없다.
- static 영역에서는 `this`, `super`를 사용할 수 없다.

## 14. 실습 프로젝트: 음악 차트 데이터 수집

### 14-1. 프로젝트 개요

추상 클래스를 이용하여 서로 다른 음악 사이트의 차트 데이터를 하나의 구조로 관리한다.

대상 사이트:

- Genie Music
- Melon Music

각 사이트에서 제공하는 데이터 수집 방식은 다르지만, 수집한 음악 데이터를 동일한 객체 구조로 관리한다.

### 14-2. 클래스 구조

```text
              MusicSystem
             (추상 클래스)
                   |
          -------------------
          |                 |
      GenieMusic         MelonMusic
          |                 |
      지니 차트 수집      멜론 차트 수집

              Music
           (데이터 클래스)
```

### 14-3. Music 클래스

음악 정보를 저장하는 데이터 클래스이다.

```java
import lombok.Data;

@Data
public class Music {

    private int mno;
    private String title;
    private String singer;
    private String album;
    private String state;
    private int idcrement;
}
```

Lombok의 `@Data`를 사용하면 Getter, Setter, toString 등의 메소드를 자동으로 생성할 수 있다.

### 14-4. MusicSystem 추상 클래스

```java
public abstract class MusicSystem {

    private static Music[] musics = new Music[50];

    public static Music[] getMusics() {
        return musics;
    }

    public Music[] musicList() {
        return musics;
    }

    public Music musicDetail(int mno) {
        return musics[mno - 1];
    }

    public void musicFindData(String title) {

        int count = 0;

        for (Music m : musics) {
            if (m != null && m.getTitle().contains(title)) {
                count++;
            }
        }

        Music[] music = new Music[count];

        int i = 0;

        for (Music m : musics) {
            if (m != null && m.getTitle().contains(title)) {
                music[i] = m;
                i++;
            }
        }
    }

    public abstract void dataCollection();
}
```

핵심:

- `dataCollection()`은 사이트마다 수집 방식이 다르므로 추상 메소드로 선언한다.
- `musicList()`, `musicDetail()` 등 공통 기능은 부모 클래스에서 구현한다.
- 자식 클래스에서 데이터 수집 기능을 각각 구현한다.

Jsoup 라이브러리를 사용하면 HTML 문서를 분석하고 필요한 데이터를 추출할 수 있다.

## 15. 핵심 개념 비교 및 정리

### 15-1. 객체지향 핵심 개념

| 개념 | 핵심 키워드 | 목적 |
|---|---|---|
| 캡슐화 | private, getter, setter | 데이터 보호 |
| 상속 | extends | 코드 재사용 |
| 다형성 | 오버로딩, 오버라이딩 | 다양한 객체 제어 |
| 추상화 | abstract, interface | 공통 규격 정의 |

### 15-2. 반드시 기억할 문법

```java
// 상속
class B extends A {}

// 인터페이스 구현
class B implements A {}

// 다형성
A a = new B();

// 오버라이딩
@Override
public void method() {}

// 추상 클래스
abstract class A {
    abstract void method();
}

// 생성자
public A() {}

// 부모 생성자 호출
super();

// 현재 클래스 생성자 호출
this();

// 람다식
Runnable r = () -> {
    System.out.println("실행");
};
```

### 15-3. 최종 정리

- 상속은 기존 클래스의 기능을 재사용하고 확장하기 위한 기술이다.
- 다형성은 부모 타입 하나로 여러 자식 객체를 제어하는 기술이다.
- 오버로딩은 같은 이름의 메소드를 매개변수에 따라 여러 개 정의하는 것이다.
- 오버라이딩은 부모 메소드를 자식 클래스에서 재정의하는 것이다.
- 추상 클래스는 공통 기능과 자식 클래스가 구현해야 할 기능을 함께 정의한다.
- 인터페이스는 클래스가 구현해야 할 규칙을 정의한다.
- 생성자는 객체 생성 시 멤버변수를 초기화하는 역할을 한다.
- Has-A는 포함 관계, Is-A는 상속 관계이다.
- 익명 클래스와 람다식은 인터페이스 구현을 간결하게 만드는 방법이다.
