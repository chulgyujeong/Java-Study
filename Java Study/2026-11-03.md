## 1. 예외처리의 개념 및 종류

### 1-1. 예외처리란?
- 정의: 프로그램 실행 중 발생할 수 있는 예외 상황에 대비하는 코드
- 목적: 예외 발생으로 인한 프로그램의 비정상 종료 방지
- 예외처리를 한다고 오류 자체가 자동으로 수정되는 것은 아님
- 예외 발생 시 적절한 복구 및 후속 처리 수행

### 1-2. 에러와 예외의 차이
- Error: 메모리 부족 등 프로그램이 정상적으로 복구하기 어려운 심각한 문제
- Exception: 파일 경로 오류, 사용자 입력 오류 등 프로그램에서 처리할 수 있는 예외 상황

### 1-3. CheckedException
- 컴파일 시점에 예외처리 여부를 검사
- 반드시 예외처리 필요
- 처리 방법
  - try ~ catch
  - throws
- 주요 관련 패키지
  - java.io
  - java.net
  - java.sql

### 1-4. UncheckedException
- 실행 중 발생하는 예외
- 컴파일러가 예외처리 여부를 강제하지 않음
- 필요에 따라 예외처리 수행
- 주로 개발자 실수 및 사용자 입력값 검증과 관련

### 1-5. 예외 클래스 계층 구조

```text
Object
  |
Throwable
  |------------------|
 Error             Exception
                       |
              -------------------
              |                 |
       CheckedException   RuntimeException
                                |
                       UncheckedException
```

## 2. 예외처리의 기본 구조

### 2-1. try ~ catch

```java
try {
    // 정상적으로 수행할 코드
} catch(Exception e) {
    // 예외 발생 시 처리할 코드
}
```

- try: 예외가 발생할 가능성이 있는 코드 작성
- catch: 예외 발생 시 실행되는 코드
- 예외가 발생하면 try 블록의 남은 코드는 실행하지 않고 catch로 이동

### 2-2. 예외 정보 확인

```java
catch(Exception e) {
    System.out.println(e.getMessage());
    e.printStackTrace();
}
```

- getMessage(): 예외 메시지 출력
- printStackTrace(): 예외 발생 위치 및 호출 경로 출력

### 2-3. 예외처리 기본 예제
- 예제 클래스: `예외처리_개념`
- Math.random()을 활용하여 0으로 나누는 상황 발생
- ArithmeticException 발생 시 catch에서 예외 처리

## 3. 예외처리 실행 순서

### 3-1. 실행 흐름
- try 블록에서 예외가 발생하지 않으면 정상적으로 다음 코드 실행
- try 블록에서 예외가 발생하면 즉시 catch로 이동
- finally는 예외 발생 여부와 관계없이 실행
- 예외처리 이후 나머지 코드 실행

### 3-2. 실습 코드
- 예제 클래스: `예외처리_실행순서`
- 10 / 0을 수행하여 ArithmeticException 발생
- catch에서 예외 메시지 출력
- finally에서 프로그램 정상 수행 메시지 출력

### 3-3. 실행 순서


## 4. 다중 Catch문

### 4-1. 다중 Catch란?
- 하나의 try 블록에서 여러 종류의 예외가 발생할 가능성이 있을 때 사용
- 발생한 예외에 맞는 catch 블록 실행
- 구체적인 예외 클래스를 먼저 작성하고 부모 예외 클래스를 나중에 작성

### 4-2. 주요 예외 클래스
- NumberFormatException: 문자열을 숫자로 변환할 수 없는 경우
- ArrayIndexOutOfBoundsException: 배열의 범위를 벗어난 경우
- ArithmeticException: 0으로 나누는 경우
- NullPointerException: null 객체를 참조하여 메소드나 변수에 접근하는 경우

### 4-3. 실습 코드
- 예제 클래스: `예외처리_다중처리`
- Scanner를 활용하여 두 개의 문자열 입력
- Integer.parseInt()로 문자열을 정수로 변환
- 배열에 저장한 후 나눗셈 수행
- 예외 종류에 따라 서로 다른 catch 블록 실행

## 5. Finally를 이용한 자원 관리

### 5-1. Finally란?
- 예외 발생 여부와 관계없이 실행되는 블록
- 주로 파일, 데이터베이스, 네트워크 등 자원 해제에 사용
- try ~ catch ~ finally 구조

### 5-2. 파일 입출력과 FileReader
- FileReader: 파일의 문자 데이터를 읽는 클래스
- read(): 문자 하나를 읽어 정수로 반환
- 파일의 끝에 도달하면 -1 반환
- close(): 파일 읽기 작업 종료 및 자원 해제

### 5-3. 실습 코드
- 예제 클래스: `예외처리_finally_사용`
- FileReader 객체를 생성하여 Java 소스 파일 읽기
- try에서 파일 읽기 수행
- catch에서 예외 메시지 출력
- finally에서 FileReader 객체가 null이 아닌 경우 close() 실행

### 5-4. 주의사항
- FileReader 객체 생성에 실패할 가능성이 있으므로 null 검사 필요
- close() 자체에서도 IOException이 발생할 수 있으므로 별도 예외처리 필요

## 6. Try-With-Resources를 이용한 자원 자동화

### 6-1. Try-With-Resources란?
- 자원을 자동으로 해제하는 예외처리 문법
- try 블록이 종료되면 자바가 자동으로 close() 호출
- finally에서 직접 자원을 해제하는 코드의 복잡성을 줄일 수 있음

### 6-2. 기본 문법

```java
try(FileReader fr = new FileReader("파일경로")) {
    // 파일 읽기
} catch(Exception e) {
    e.printStackTrace();
}
```

### 6-3. AutoCloseable
- try-with-resources를 사용하려면 해당 자원이 AutoCloseable 인터페이스를 구현해야 함
- FileReader는 Closeable을 구현하며 Closeable은 AutoCloseable을 상속
- 따라서 FileReader는 try-with-resources 사용 가능

### 6-4. 실습 코드
- 예제 클래스: `예외처리_자원자동화처리`
- FileReader를 이용하여 Java 소스 파일 읽기
- read()를 반복 실행하여 파일 내용을 출력
- try 블록 종료 시 close() 자동 실행

### 6-5. Finally 방식과 비교

| 구분 | Finally | Try-With-Resources |
|---|---|---|
| 자원 해제 | 직접 close() 호출 | 자동 close() |
| 코드 길이 | 상대적으로 김 | 간결함 |
| 자원 관리 | 직접 관리 | 자동 관리 |
| 주요 용도 | 기존 자원 관리 방식 | 권장되는 자원 관리 방식 |

## 7. 예외 회피 (throws)

### 7-1. 예외처리 방법
- 예외 복구: try ~ catch를 사용하여 직접 처리
- 예외 회피: throws를 사용하여 호출한 메소드에 예외처리 책임 전달

### 7-2. throws 기본 문법

```java
public static void test() throws Exception {
    // 예외 발생 가능 코드
}
```

### 7-3. CheckedException과 UncheckedException
- CheckedException: 예외처리를 하지 않으면 컴파일 오류 발생
- UncheckedException: throws를 사용하지 않아도 컴파일 가능
- throws RuntimeException은 선언할 수 있지만 필수는 아님

### 7-4. 실습 코드
- 예제 클래스: `예외처리종류`
- fff(): throws Exception
- ggg(): throws RuntimeException

## 8. 주요 UncheckedException 종류 및 실습

### 8-1. ArithmeticException
- 0으로 나누는 경우 발생
- 실습 메소드: aaa(int a, int b)

### 8-2. NullPointerException
- null 상태의 객체에서 메소드나 변수에 접근하는 경우 발생
- 실습 메소드: bbb(String data)

### 8-3. NumberFormatException
- 숫자 형식이 아닌 문자열을 정수로 변환하는 경우 발생
- 실습 메소드: ccc(String num)

### 8-4. ArrayIndexOutOfBoundsException
- 배열의 유효한 인덱스 범위를 벗어나는 경우 발생
- 실습 메소드: ddd()

### 8-5. ClassCastException
- 실제 객체의 타입과 호환되지 않는 타입으로 강제 형변환하는 경우 발생
- 실습 메소드: eee()

### 8-6. 실습 코드
- 예제 클래스: `예외처리종류`
- 각 예외 상황을 메소드별로 분리하여 실습
- main()에서 각 메소드를 호출하여 예외 확인

## 9. 가변인자 (Variable Arguments)

### 9-1. 가변인자란?
- 메소드에 전달하는 매개변수의 개수를 유동적으로 설정하는 문법
- 자료형 뒤에 ...을 사용
- 내부적으로 배열 형태로 처리

### 9-2. 기본 문법

```java
public static void display(int... a) {

}
```

### 9-3. 호출 방법

```java
display(10);
display(10, 20);
display(10, 20, 30);
```

### 9-4. 특징
- 매개변수 개수 제한 없이 전달 가능
- 가변인자는 메소드의 매개변수에서 한 번만 사용 가능
- 여러 매개변수가 있다면 가변인자는 마지막에 선언해야 함

### 9-5. 실습 코드
- 예제 클래스: `예외처리_1`

## 10. 숫자 야구 게임 - Swing 이벤트 처리 응용

### 10-1. Swing GUI 구성
- JFrame: 윈도우 화면 생성
- JButton: 버튼 생성
- JTextField: 한 줄 입력창
- JTextArea: 여러 줄 출력창
- JScrollPane: 스크롤 기능 제공
- JPanel: 컴포넌트 배치

### 10-2. 이벤트 처리
- ActionListener: 버튼, 메뉴, 텍스트 필드 등의 이벤트 처리
- actionPerformed(): 액션 이벤트 발생 시 호출

### 10-3. 주요 이벤트 리스너

| 이벤트 리스너 | 주요 메소드 | 용도 |
|---|---|---|
| ActionListener | actionPerformed() | 버튼, 메뉴, 텍스트 필드 |
| MouseListener | mouseClicked(), mousePressed(), mouseReleased(), mouseEntered(), mouseExited() | 마우스 이벤트 |
| KeyListener | keyTyped(), keyPressed(), keyReleased() | 키보드 이벤트 |
| ItemListener | itemStateChanged() | 체크박스, 콤보박스 등의 선택 상태 변경 |

### 10-4. 숫자 야구 게임 주요 기능
- 시작 버튼: 게임 시작 및 컴퓨터 난수 생성
- 전송 버튼: 사용자 입력값 전달
- 종료 버튼: 프로그램 종료
- JTextField: 사용자 숫자 입력
- JTextArea: 게임 진행 결과 출력

### 10-5. 난수 생성
- Math.random()을 활용하여 1~9 사이의 난수 생성
- 중복되지 않는 세 자리 숫자 생성
- 배열을 이용하여 컴퓨터 숫자 저장

### 10-6. 사용자 입력 및 유효성 검사
- 세 자리 정수 입력 여부 확인
- Integer.parseInt()를 이용한 문자열 정수 변환
- 중복 숫자 입력 제한
- 0 입력 제한
- 잘못된 입력에 대한 예외처리

### 10-7. 스트라이크와 볼 판정
- 컴퓨터 숫자와 사용자 숫자를 각각 배열에 저장
- 같은 인덱스에서 숫자가 일치하면 Strike
- 다른 인덱스에서 숫자가 일치하면 Ball
- 3 Strike가 되면 게임 종료 또는 새 게임 진행

### 10-8. 프로그램 종료
- dispose(): JFrame 윈도우 자원 해제
- System.exit(0): JVM 프로그램 종료
